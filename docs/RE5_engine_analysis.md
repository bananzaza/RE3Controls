# 引擎侧分析：动作类、模型槽位与"投掷收势抽搐"

目标二进制：`analysis\game_image_layout.bin`（解密后的 PE 镜像，ImageBase 0x00400000，26 MB）。
工具：pefile + capstone（本机 Python 3.14）。IG5 车道在本会话不可用（宿主预算限制），因此这里是纯静态分析。

## 1. 动作类命名表（从引擎字符串表提取）

引擎以 `cPlAction_pl_act_*` 命名每个玩家动作类，字符串位于 `.data` 的 0x01045EE8–0x01047074：

| 名称 | 字符串地址 |
|---|---|
| `pl_act_wait` / `relax` / `walk` / `walk_l` / `walk_r` / `run` / `back` | 0x01045F04–0x01045F94 |
| `pl_act_turn_l/r/180` | 0x01045FAC–0x01045FDC |
| `pl_act_wall_*`（掩体全套） | 0x01045FF8–0x01046280 |
| `pl_act_weapon_ready_begin/loop/end`、`attack_*` | 0x01046280 起 |
| **`pl_act_item_use_my_first/second`**（自用道具，含急救喷雾） | 0x01046C54 / 0x01046C78 |
| `pl_act_item_use_partner_*`、`item_hand_partner_*`、`item_load_*` | 0x01046C9C–0x01046D6C |
| `pl_act_coop_item_load_*` | 0x01046FF8 起 |

结论：**急救喷雾走的是 `item_use_my_first/second` 这一族动作**，此前我们把 `0x20`（换枪）
误当成道具使用，方向从一开始就是错的；这一类动作的数值 id 需要一次运行时采样确定
（静态表里字符串与 id 的绑定在初始化代码里，且 vtable 会被保护壳重定位，静态推断不可靠）。

## 2. 模型系统（腿部层的底层）

- `uModel::setMotion(slot, no, inter, start, speed, flags)` @ **0x0059E880**
  - `cmp edx, [ebx+0x374]` → **slot 数量上界**（槽位索引越界直接返回 false）；
  - 每个槽位结构 **0xE0 字节**：`lea eax,[edx+4]; imul eax,0xE0; add eax,ebx`
    → 槽位数组从对象 +0x380 开始，索引 i 的结构在 `model + (i+4)*0xE0`；
  - `[eax+0xC]` 存速度（`speed` 参数），`[eax+4]` 是片段号（`0xFFFF` 表示空槽）。
- `uModel::blend()` @ **0x00588230**：每帧把所有槽位混合成骨骼。
  - 入口先 `call 0x48AA20`（更新前处理），再读 `[ebx+0xA80]`（姿势数据指针），为 0 直接跳到收尾；
  - 之后用 `[ebx+0x340/0x344/0x348]` 三个分量与常量 `0x11AF820/24/28` 相乘求和（根运动/位移换算）。

**这解释了两件事：**

1. **"关掉腿部层"为什么会让角色站住**：层不写槽位，看起来什么都没发生，但 mod 里
   `KbSetDriving(...)` 的 `walkAllowed` 同时决定"摇杆是否交给游戏"，关层即断掉移动输入；
2. **"层开着但输入为 0"为什么会抽搐**：槽位仍被层以 0 速度写入，而游戏自身也在同一槽位
   （投掷收势片段）写入，两条来源每帧交替成为主导 → 骨骼混合权重抖动。
   这正是五种方案里"关层 / 清输入 / 静默窗口"全部失败的原因：它们都在改**输入**，
   而抖动发生在**槽位写入权**上。

## 3. 与已知问题的对应

| 问题 | 引擎侧解释 |
|---|---|
| 投掷收势腿部抽搐 | 投掷动作与腿部层争夺同一 `uModel` 槽位的写入权；`blend()` 每帧按权重混合，两个来源交替 → 骨骼抖 |
| 挥刀不能跑 | `setMotion` 的 `speed` 参数（`[slot+0xC]`）决定播放速率；`MoveSpeedFor(ch,5)` 在非移动态返回 1.0，等于走路速度 |
| 交互/攀爬时瞄准转身 | 攀爬动作 id 为哨兵 `0x80000000`，未被 `busyAction` 范围覆盖 |
| 换枪误判 | `0x20` 是 `pl_act_change*` 一族（换枪），不是投掷 |

## 4. 下一步（引擎侧可做的）

1. **确定 `item_use_my_first` 的数值 id**：运行时 CE 采样一次（喷雾时读 `ch+0x10E0`），
   然后纳入可走集合 —— 这是纯数据补齐；
2. **投掷抽搐的正解**：不要碰输入，也不要关层，而是**让层在投掷窗口内不写槽位**，
   同时保留 `walkAllowed`（即把"层运行"与"写槽位"解耦）。当前代码里两者被绑在一起，
   这是架构层面的限制，需要给 `AimWalkUpdate` 加一个"只驱动摇杆、不写槽位"的模式。
3. 若要进一步确认槽位归属，可在 `uModel::blend` 入口读 `[ebx+0xA80]` 与各槽位的
   `[slot+4]`（片段号）记录，即可看出投掷时哪个槽位被谁写了。
