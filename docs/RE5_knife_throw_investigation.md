# 挥刀移动 / 投掷抽搐：完整调研记录（1.9.4 线）

记录时间：2026-11-03。适用版本：RE3Controls 1.9.4-mod63x → mod147（本 fork）。
证据来源：CE 内存采样、Ghidra（IG5）反编译、capstone 静态反汇编、游戏日志。

---

## 一、结论摘要

| 问题 | 结论 |
|---|---|
| 快速挥刀（`knife_attack`，id `0x27`）期间无法移动 | **引擎行为**：动作开始时置移动锁并清移动向量，mod 无法在锁定帧内驱动移动 |
| 急救喷雾 / 自用道具（`item_use_my_first/second`，`0x61/0x62`）不能移动 | 同上机制 |
| 投掷收势腿部抽搐 | **mod 介入导致**；完全不介入后消失（当前版本即如此） |
| 持刀走/跑（`0x22–0x24`）、瞄准走、换弹走、收枪走、开火后走 | 正常 |

因此 mod147 的处理是：**不试图突破引擎移动锁，也不对投掷做任何特殊处理**。

## 二、引擎侧关键事实（有代码级证据）

### 2.1 动作 id 表（从静态注册序列反解，运行时验证一致）

静态初始化里每个动作类都被注册（`push <类名>; push <size>; mov ecx,<表>; call 0x6D04F0`）。
按 `pl_act_wait` 校准为 `0x00` 后得到完整表，与运行时观测完全吻合：

| id | 名称 | 用途 |
|---|---|---|
| `0x00–0x09` | wait / relax / walk / run / back / turn | 移动 |
| `0x1B/0x1C/0x1D` | weapon_ready_begin/loop/end | 举枪三态 |
| `0x1E` | weapon_fire | 开火（**手雷投掷也走这里**） |
| `0x1F` | weapon_reload | 换弹 |
| `0x20/0x21` | weapon_change(_ready) | 换枪 |
| `0x22–0x24` | knife_ready_begin/loop/end | 持刀 |
| `0x25/0x26` | knife ↔ gun 互切 | |
| `0x27` | knife_attack | 挥砍（移动锁） |
| `0x28–0x2F` | jump / bump / fence / ladder / provoke | 交互 |
| `0x30–0x58` | attack_* / avoid_* | 体术/闪避 |
| `0x59–0x60` | item_get / put / dump | 拾取放置 |
| `0x61/0x62` | item_use_my_first/second | 自用道具（喷雾，移动锁） |
| `0x63–0x68` | item_use_partner / item_load | 同伴/装填 |
| `0x85/0x86` | plaga_stick_in/out | 寄生虫附着（**曾被误当投掷**） |
| `0x88+` | damage_* | 受击 |

### 2.2 动作类的 vtable（运行时）

用 CE 采样并拟合出线性关系：

```
vtable(id) ≈ 0x01043FE8 + id × 0x2C        （id ≥ 0x1F 有 +4 漂移）
```

验证点：`0x00 → 0x01043FE8`、`0x1C → 0x010444B8`、`0x1E → 0x01044510`（实测一致）、`0x20 → 0x0104456C`（+4）。

vtable 槽位含义：

| 槽 | 含义 |
|---|---|
| 0–3 | 构造/析构/类型查询（公共） |
| 4 | 返回类静态数据（`mov eax, imm; ret`） |
| 5 | 参数设置（写 `[ecx+0xc]` / `[ecx+0x10]`） |
| 6 | 基类更新（`call 0xC8B1E0`） |
| **7** | **动作每帧执行**（Fire = `0x00C89F30`） |

### 2.3 移动锁（这是挥砍/道具不能移动的根因）

`0xB7A8F0`（动作开始时调用）：

```asm
00B7A908  call 0xB7A630
00B7A90D  or   dword [esi+0x2D7C], 0x80000000   ; ← 置"移动锁"位
00B7A917  push 0
00B7A91B  call 0xB73BF0                          ; ← 清空移动向量
```

`ch+0x2D7C` 的 bit31 即"输入/移动锁定"。这就是为什么：

- 层参数（`walkAllowed`）全开、摇杆满量、`got=1`，角色仍不动；
- 清掉该位只能恢复"动画自带的前冲"，无法恢复侧向或奔跑；
- 唯一能让挥砍移动的是**进入引擎的瞄准移动路径**（玩家按住瞄准键时确实能走能跑），但 mod 模拟该状态会破坏方向解释与投掷动作。

### 2.4 模型与腿部层

- `uModel::setMotion(slot, clip, …)` @ `0x0059E880`：槽位结构 `0xE0` 字节，数组从 `model + (slot+4)*0xE0`，`[slot+0xC]` = 速率，`[slot+4]` = 片段号（`0xFFFF` 空）。
- `uModel::blend()` @ `0x00588230`：每帧把所有槽位混成骨骼，根位移由 `[model+0x340/344/348] × 常量` 计算。
- `aimwalk.cpp` 的层通过 `setMotion` 写同一批槽位 → 与动作动画**争用**，这是投掷抽搐的机制。

### 2.5 动作注册机制

`0x6D04F0` 反编译：类名参与哈希（`FUN_006E7910(name)`），id 来自 `hash & 0x7FFFFFFF`，
vtable 来自参数（缺省 `0x011AF714`）。因此**运行时 id 与"注册顺序表"存在偏移**，
按单个 id 判断一整类动作并不可靠（喷雾实测同时出现 `0x5F/0x60` 与 `0x61/0x62`）。

## 三、尝试过的方案与结果（挥刀移动）

| # | 版本 | 做法 | 结果 |
|---|---|---|---|
| 1 | mod63x | 无处理（挥砍站定） | 无 bug，但挥砍不能走 |
| 2 | mod135 | 删除所有刀专用逻辑，走通用 aim-walk | 持刀正常，挥砍仍站定 |
| 3 | mod136 | 把刀加入 `moveSteer` | 全部持刀变成"只能往前" |
| 4 | mod139 | 清 `ch+0x2D7C` 的锁位 | 只能前进 |
| 5 | mod140 | 解锁 + 写摇杆 | 按住瞄准键可走/跑 |
| 6 | mod141 | 解锁 + 转身 + 前向摇杆 | 无变化 |
| 7 | mod142 | 挥砍帧抬举枪位（模拟瞄准） | 两种挥刀都变"只能往前"，投掷抽搐复发 |
| 8 | mod143/144 | 复原 mod140 组合 | 仍不达预期 |

投掷抽搐的尝试（另计 6 种）：关腿部层、清方向位、30 帧静默窗口、源头清摇杆、让出相机、
相位判定（`Fire` 的 `phase ≥ 0x20`）—— **全部无效或带来更严重回归**。

**最终处理**：完全不介入投掷（抽搐消失）；挥砍保持引擎行为（站定）。

## 四、如果以后要重做这条功能

推荐路径（按优先级）：

1. **反编译 `0xB7A8F0` 的调用方**（动作类 slot 6/7），确认能否只跳过"清移动向量"那一步
   而保留动作状态机；这比清锁位或模拟瞄准更贴近语义。
2. 若必须进入瞄准路径，需要同时接管：方向解释（相机坐标）、举枪位、以及投掷/换枪的状态机，
   风险很高，必须逐项验证。
3. 任何改动都应在 `analysis\src_backup_mod132_20261102-234738\` 与提交 `bc41469` / `ec44a26` 之间可回退。
