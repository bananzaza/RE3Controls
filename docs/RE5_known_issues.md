# RE3Controls（本 fork，1.9.4-mod107）：已知问题与修复状态分析

本文件记录每一项"修过 / 没修好"的问题：现象、证据、根因判定的把握程度、试过的方案、
以及下一步该怎么查。证据全部来自本机实测（内存采样、反汇编、日志），不是推测。

## 一、已确认修复（有机制解释）

| # | 问题 | 机制 | 证据 |
|---|---|---|---|
| 1 | 开火后枪举着不放、不能动 | `Fire::update` 相位停在 2，等 `[对象+0x20]` 计时器跨阈值；每帧把计时器顶到 999 让等待结束 | CE 转储 51 帧字节不变 + 反汇编 0xC8A4A4 块的 `comiss/jb` |
| 2 | 空仓自动换弹不能走 / 不能转向 | 自动换弹不经过 mod 的 `reloadMove`；把 `Reload` 动作本身纳入可走 + 转向 | 版本迭代验证（mod63v/w） |
| 3 | 收枪后方向固定 | `ReadyEnd` 期间未接管方向 | mod63x 验证通过 |
| 4 | 投掷/换枪后不能动、误触发 | `aid 0x20` 是换枪（`re5.h:128` 明确写了），曾被当成投掷处理，导致每次换枪被强按 `P_RT` → 自动瞄准+换弹 | mod104 修复并验证 |
| 5 | 挥刀卡住 | `KnifeAttack(0x2A)` 与开火共用同一判定，被计时器压制逻辑误伤 | 需要同时校验动作 id；已修 |
| 6 | 挥刀不能跑 / 速度异常 | 腿部层在挥砍时未喂入；`MoveSpeedFor(ch,5)` 在非移动态返回走路速度 | mod95-97：向前用游戏原速、其它方向用瞄准行走速度 |
| 7 | 交互/体术/攀爬时瞄准会转身 | `busyAction` 未覆盖攀爬哨兵 `0x80000000` | mod86 起 |
| 8 | 虚表比较静默失效 | 游戏被保护壳重定位，硬编码 VA 全部不成立 | 需要 `VaOf()` 换算；日志实测虚表偏移 |

## 二、未解决（含证据与下一步）

### A. 投掷收势时腿部抽搐（唯一仍开放的玩法问题）

- **现象**：丢手雷后约 0.5 秒内，腿部抖动；期间若按住方向更明显。
- **已知事实**：
  1. 投掷动作链实测为 `aid=0x85 → aid=0x00(Wait) → aid=0x02(Walk)`（日志时间戳可查）；
  2. 方向位置零时仍抽（排除"摇杆残留"作为唯一原因）；
  3. 把腿部层整段关闭 → 变成"不能动 + 更明显";
  4. 30 帧静默窗口 → 不能动；
  5. 清 pad 摇杆源（`st.lx/ly`、`P_LMag`）→ 仍抽。
- **结论（把握较高）**：抽搐来自引擎自身的动画混合权重（投掷收势与移动姿势交叉），
  不在 mod 可写的输入层。五种方案全部失败，与上游所有 fork 的结论一致（他们干脆不处理投掷）。
- **下一步（唯一可行）**：改用 `AimWalkUpdate` 的"不喂输入但保持层运行"的第三种状态——
  即传 `walkAllowed=true, pace=0, stick=0`，让层输出"静止帧"而不是关闭。这是唯一没试过的组合。

### B. 急救喷雾/道具使用时不能移动

- **现象**：使用治疗喷雾时角色站定。
- **已知**：该动作不在动作表常量里；`aid 0x20` 是换枪，不是道具使用。
- **下一步**：用一次 CE 采样取到喷雾时的 `aid`（约 10 秒），再纳入可行走集合。
  这是纯数据缺失，不是机制问题，把握高。

### C. 佣兵倒计时结束后自己走（mod107 已修，待验证）

- **机制**：`ApplyControls` 的两条短路返回（键鼠读取失败 / 手柄丢失）不写 pad，
  脚本态期间 pad 保留进入前的方向，控制权交还时被当成"仍按着"。
- **已修**：这两条路径现在主动清 `P_LS_DIRS` 与 `P_LMag`。
- **待验证**：进佣兵，倒计时期间按方向，观察 GO 后是否静止。

### D. 狙击镜 / 激光（引擎侧限制，不计划修）

- 开镜视角由武器相机绘制，忽略 mod 可写字段（射击点、瞄准点、pad 输入）；
- 激光只在手柄路径绘制；键鼠只有准星。

## 三、跨版本教训（避免重复踩坑）

1. **虚表地址不可当常量**：保护壳会重定位，必须 `VaOf()`；能用动作 id 就不要用虚表。
2. **动作 id 才是稳定标识**：实测 `0x1E=开火`、`0x20=换枪`、`0x21=瞄准中换枪`、`0x2A=挥砍`、`0x85=投掷`。
3. **`MoveSpeedFor` 在非移动态返回 1.0**（走路速度），不能直接当跑步速度用。
4. **改 `walkAllowed` 会影响普通行走**（键鼠的摇杆只在层被允许时传给游戏），
   这是历史上"不能走路"回归的根源。
5. **诊断日志必须限流**：`HookKeyOn` 每帧数百次调用，限流 1/30 仍产生 1.5 万行/局。
6. **一次只改一处**，并保留可回退的提交点；本仓库的 `f8330ae`（mod67）是已验证的稳定基线。
